# ドキュメント

## 目次

- `docs/`: ドキュメントを入れるリポジトリ
  - `pm/`: プロジェクト管理
  - `design/`: 設計書
    - `analysis/`：要求分析（ユーザー視点のニーズや課題）
      - `user-needs.md`：ユーザーニーズ・課題洗い出し（アイデアメモ含む）
      - `stakeholder-analysis.md`：ステークホルダー分析
      - `business-goals.md`：ビジネス目標
    - `specification/`：要件定義（システム仕様）
      - `functional-requirements.md`：機能要件一覧（ユーザーストーリー・ユースケース）
      - `non-functional-requirements.md`：非機能要件（システム要件としてのまとめ）
      - `use-case-scenarios.md`：ユースケースシナリオ詳細
    - `basic/`：基本設計（画面構成、API設計など）
      - `system-architecture.md`：システム構成図・アーキテクチャ概要
      - `screen-transition.md`：画面一覧・画面遷移図
      - `db-overview.md`：概念ER図（テーブル一覧・関係）
      - `api-overview.md`：API一覧（REST/GraphQL設計の概要）
    - `detail/`：詳細設計（ロジック、データ構造など）
      - `components.md`：UIコンポーネント設計（props、状態、バリエーション、Storybook対応）
      - `api-spec.md`：API詳細仕様（OpenAPI/Swagger仕様）
      - `db-schema.md`：DB詳細設計（PrismaモデルやDDL定義）
      - `sequence.md`：処理フロー（Mermaidシーケンス図）
      - `error-handling.md`：エラー・例外処理設計
       - `validation-rules.md`：入力バリデーション仕様（Zodやサーバ検証含む）
    - `policy.md`：設計方針・規約など
  - `test/`: test仕様書
    - `unit/`：単体テスト（関数やコンポーネント単位での動作検証）
      - `unit-test-cases.md`：単体テスト観点リスト（関数・コンポーネント単位）
      - `unit-test-guide.md`：Jestテスト実装ガイドライン（命名規則、モック方針）
    - `integration/`：結合テスト（モジュールやAPI層の連携検証）
      - `integration-test-cases.md`：結合テスト観点（API連携、DB結合など）
    - `system/`：システムテスト（E2Eテストや性能テスト、負荷テストなど）
      - `e2e-test-cases.md`：E2Eテストシナリオ（ユーザー操作のフロー検証、Playwright対応）
      - `e2e-guide.md`：Playwright設定・実行手順
      - `performance-test-plan.md`：負荷・耐久・スケーラビリティ試験計画
      - `performance-tools.md`：使用ツール（k6, Artilleryなど）の使い方・評価方法
    - `acceptance/`：受け入れテスト（ユーザー視点のニーズに対する検証）
       - `acceptance-test-cases.md`：受け入れテスト観点・シナリオ（顧客要件に対する検証）
      - `acceptance-criteria.md`：受け入れ基準（合格条件）
    - `policy.md`：テスト方針・テスト戦略など
  - `index.md`: 目次（このファイル）
